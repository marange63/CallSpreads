# CLAUDE.md

Guidance for working in this repo. Keep it current when conventions change.

## What this is
A personal tool for finding and monitoring **call debit spreads** on US equity/index options. Five surfaces:
- **Call Spread Finder** (`/`) — scans an option chain for spreads matching filters, with a results table, a composite **Score** column, and a theoretical-value chart.
- **My Positions monitor** (`/positions`) — live risk/P&L for saved positions.
- **Scatter** (`/scatter`) — plots the Finder's current results as two side-by-side, independently-configurable scatter panels; opened from the Finder and kept in sync with it (see Scatter below).
- **Spread Curve** (`/curve`) — one spread's theoretical value across spot, with sliders for spot / days-to-expiry / IV shift; opened by clicking a row on *either* table (see Curve below).
- **Dip Scanner** (`/dip`) — pre-screens a curated watchlist of large caps for pullbacks and ranks them by a composite *Dip Score*; click a candidate to open the Finder pre-loaded with the dip-buy screen (see Dip Scanner below).

## Architecture
- **Two Python files.** `spx_call_spread_finder.py` (~5500 lines) is the app: pure stdlib `http.server`/`socketserver`; the four pages are hand-written HTML/CSS/JS held as big Python strings:
  - `HTML_PAGE` → the Finder (`/`).
  - `POSITIONS_PAGE` → the monitor (`/positions`).
  - `SCATTER_PAGE` → the Scatter view (`/scatter`).
  - `CURVE_PAGE` → the Spread Curve (`/curve`).
  - `DIP_PAGE` → the Dip Scanner (`/dip`) — self-contained static HTML, no `.replace()` tokens; all data via `/api/dipscan` + `/api/watchlist`.
- **Shared JS lives in `.replace()`-injected constants, not duplicated copies**: `BS_JS` (`jsNormCdf`/`jsBsCallPrice` — the *only* copy of the client-side BS math, token `__BS_JS__`, injected into the Finder, Scatter and Curve), `CURVE_LINK_JS` (`openCurve`/`pruneCurveKeys`/`refreshOpenCurves`, token `__CURVE_LINK__`, injected into the Finder and monitor), plus the older `PNL_CHART_JS`/`SPREAD_TOOLTIP_JS`. Adding a copy of one of these instead of a token is a regression — `check_pages.py`-style verification asserts `jsBsCallPrice` is defined exactly once.
- **`price_sources.py` is the market-data seam**: `PriceSource` ABC + `YahooSource` + registry (`SOURCE_CLASSES`/`SOURCES`, `get_source`/`set_active_source`/`register_sources`). It owns the yfinance import/auto-install; **the main file must contain no direct `yf.*` calls**. Contract: all methods take Yahoo-style symbols (`^SPX`, `^VIX` — subclasses translate via `map_symbol`) and return yfinance-shaped data (Yahoo column/key names). A new vendor = subclass implementing `get_expirations` + `get_option_chain` (Tier 1) + one `SOURCE_CLASSES` entry; Tier-2 reference data (`get_daily_closes`, `get_daily_closes_batch`, `get_previous_close`) defaults to delegating to Yahoo. **`MarketDataSource` (marketdata.app) is implemented**: token + `feed` in `sources.json` (unconfigured vendors are skipped silently at registration); requests calls-only chains per expiration; `feed=cached` (1 credit/call) is tried first and auto-dropped for the session on HTTP 402 (trial/free plans can't control the feed and serve delayed options — subscribe to the Trader plan for near-real-time). Source failures surface as errors — deliberately no silent Yahoo fallback. The active (options) source is server-global: dropdown on both pages, `GET/POST /api/source`, persisted in `sources.json`. **The feed is switchable at runtime** (no restart): `feed_options`/`get_feed`/`set_feed` on the source (MarketData exposes `cached`/`live`), driven by `POST /api/source/feed` and a feed dropdown on the monitor that shows only when the active source has `feed_options`; the choice persists to `sources.json`. **Split spot source**: a second server-global (`set_spot_source`/`get_spot_source_name`, top-level `"spot"` key in `sources.json`, `POST /api/source/spot`, "spot:" dropdown next to the source dropdown on both pages) picks which vendor supplies the *underlying spot*, independently of the options source; `""` = "with options" (the chain's native bundled quote). Mechanism: each source's `get_option_chain` calls the base-class `_spot_override(symbol)`, which fetches `get_underlying_quote` (Yahoo: 1-min-candle price memoized ~5s; MarketData: quotes endpoint, 1 credit, memoized ~5s) from the override source and merges it into `.underlying` — no-op when the override is the chain source itself or fails (native fallback, never an error). Point: MarketData's Trader plan serves real-time *options* but ~15-min-delayed *equities*, so options=MarketData + spot=Yahoo is the useful combo (also saves the per-chain quote credit). The old per-vendor `"spot_source"` config key is migrated to `"spot"` on first load, then inert.
- `main.py` is an **unused** PyCharm stub — ignore it.
- Backend entry points: `fetch_and_find_spreads(...)` (Finder scan) and `fetch_position_quotes(...)` (monitor). Shared Black-Scholes toolkit (`bs_call_price`, `bs_call_delta`, `bs_gamma`, `bs_vega`, `bs_call_theta`, `implied_vol`) is defined once near the top and reused by both.

## Running & testing
- Launch: `Launch CallSpreads.bat`, or `python spx_call_spread_finder.py`. It **auto-detects a free port** starting at 8765 and prints a banner with the URL.
- The startup banner uses box-drawing characters; `main()` reconfigures stdout/stderr to UTF-8 so redirecting output to a file works. If you invoke Python yourself in a cp1252 shell, set `PYTHONIOENCODING=utf-8`.
- Quotes come from **Yahoo via `yfinance`** (auto-installed if missing). Option quotes are **~15 min delayed**; the underlying `regularMarketPrice` is fresher.
- **Yahoo rate-limits repeated option-chain scans** — heavy back-to-back Finder scans during testing will start hanging/returning empty. Space them out; prefer verifying page structure (serving `/` doesn't hit Yahoo) over repeated live scans.
- **Test mode** is the intended way to test with the market closed: it caches each underlying's option chain so repeated Finder scans and the monitor's 30s auto-refresh reuse frozen data instead of re-fetching. Toggle it live via the **LIVE/TEST badge** on both pages; it sets `?test=1` on the API calls. See the Test/Production mode gotcha below.
- **Offline verification (preferred over live scans):** `python -c "import ast; ast.parse(open('spx_call_spread_finder.py',encoding='utf-8').read())"` for Python; for the page JS, extract the `<script>` blocks (substituting placeholders — `{RISK_FREE_RATE_PCT}` for the Finder; `__PNL_CHART__`/`__SPREAD_TOOLTIP__` for Scatter) and run `node --check`; and use fake-ticker unit tests for backend logic. This sidesteps Yahoo throttling entirely.
- When testing, parse the port from the banner. Launched server processes hold ports (8765+); kill stray ones when done so they don't accumulate.

## Data files (all gitignored — runtime state)
- `positions.json` — saved monitor positions.
- `templates.json` — saved Finder parameter sets.
- `beta_cache.json` — per-day beta cache for the monitor's beta column.
- `chain_cache.pkl` — disk mirror of the Test-mode option-chain cache (pickled chain snapshots + expiration lists), loaded at startup, deleted by "Clear cache".
- `alerts.json` — Adj P&L alert config (secret random ntfy topic + thresholds) and the once-per-day sent latches; auto-created on first run.
- `sources.json` — active options source (`"active"`), spot-source override (`"spot"`, `""` = with options) + per-source config (vendor API keys, `feed`). Missing file = Yahoo, native spot.
- `watchlist.json` — the Dip Scanner's curated large-cap universe (JSON array of tickers). Seeded from `DEFAULT_WATCHLIST` on first run; edited in the `/dip` UI via `GET/POST /api/watchlist`.
- `dip_cache.json` — per-calendar-day cache of the Dip Scanner's computed signals (`{date, asOf, symbols, vixRank, candidates}`); rewritten on a cache miss or `?force=1`, keyed by date + exact symbol set.

## Conventions & gotchas
- **`HTML_PAGE` is a raw string**; `{RISK_FREE_RATE_PCT}` is substituted with `.replace()` at serve time — it is *not* an f-string, so literal `{}` in the page's JS is safe.
- **`SCATTER_PAGE` is also a raw string** with the same trap: `__PNL_CHART__` and `__SPREAD_TOOLTIP__` are `.replace()`-substituted at serve time with the `PNL_CHART_JS` / `SPREAD_TOOLTIP_JS` constants (self-contained copies of the Finder's BS/chart/tooltip helpers).
- **Test/Production mode (chain caching):** shared helpers `get_option_chain(symbol, exp, test_mode)` / `get_expirations(symbol, test_mode)` / `clear_test_cache()` back a module-level cache **keyed by the active source's name** (`(source, symbol, exp)`), so frozen Yahoo data is never served while another source is active. In test mode each chain and expiration list is fetched **once** and reused; in prod every call re-fetches (from the active `PriceSource`). Wired through both `fetch_and_find_spreads(..., test_mode=)` and `fetch_position_quotes(..., test_mode=)` (incl. the monitor's `get_atm_iv_30d` / `get_index_sigma_1d`). Routes: `?test=1` on `/api/spreads` and `/api/positions/quotes`; `/api/clear_cache` empties it. **The cache is shared across the Finder and monitor**, so "Clear cache" on either page clears both. Beta is separately disk-cached daily; the index σ comes from a small `^VIX`-family quote, not an option chain.
- **The chain cache is disk-persistent** (`chain_cache.pkl`, format v2 = source-prefixed keys; v1 files migrate to `yahoo` keys on load): every `PriceSource` returns chains pre-frozen as plain picklable snapshots (`.calls`/`.puts`/`.underlying`/`fetched_at` — Yahoo's normalizer is `_snap_chain` in `price_sources.py`) and test-mode fetches are write-through saved — but **only chains with ≥1 live two-sided quote** (`_chain_has_live_quotes`), so weekend/after-hours fetches with zeroed bid/ask can't poison the cache (they still cache in memory for the session). `main()` reloads the file at startup; "Clear cache" deletes memory **and** the file. Capture workflow: scan in Test mode while quotes are live (e.g. Friday session) and weekend restarts keep working off that frozen data. **Yahoo zeroes option bid/ask outside market hours (worst on weekends)** — live scans then return no spreads by design (the OTM filter requires `bid>0 & ask>0`).
- **Runtime UI state lives in `localStorage`** (namespaced, per-browser): `finderScoreWeights` / `finderScoreOiTarget` / `finderScoreOpen` (Score panel), `finderTestMode`, `posTestMode`, `posMarketHoursOnly` (monitor auto-refresh gate, default on), `posAutoRefresh` (monitor auto-refresh master switch, default on), `finderScatterData` (see Scatter), `spreadCurve:<id>` + `curveYMode` (see Curve), `betaIndexSymbol`, `sigmaMult`, plus saved templates. Reuse these keys rather than inventing parallel ones.
- **Units:** premium/dollar UI fields are **dollars = option points × 100** (the 100x multiplier). Width is in **points**. Mixing them bites: e.g. a $9,000 *min premium* against a 100-pt spread (whose max value is only $10,000) returns nothing.
- **Per-contract vs. position-level:** many metrics exist in both forms. Screen a spread's *character* on the **per-contract** value (independent of size): `Min Net Delta` filters per-contract Δ/Contract; `Min Short-Leg Price` filters the short call's quoted price. `contracts` is auto-sized = `floor(Max Premium ÷ cost-per-spread)`, so position-level values scale with budget — don't filter structure on them.

## Finder form (organized by function)
- **Scan** (Ticker, Expirations) · **Filters** (screen which spreads return) · **Output & scenario** (shape result *columns*, don't screen) · **Model inputs** (Rate, Commission — collapsed, feed the math).
- Two easily-confused knobs, different units: **Recovery move %** = an *underlying* move (drives the "Return @ +X%" column); **P&L target (% of cost)** = a *return on premium* (drives the path-aware "P(+X%)" Monte-Carlo probability column and its siblings below). Neither screens spreads.
- **Scenario columns are exact BS reprices, not Taylor expansions**: Leverage, Return @ +X% and Return 1σ 1d all come from repricing both legs at the shocked underlying (leg IVs and T held fixed), so they respect the spread's value cap at width. Δ/Prem is the linear part and **Γ/Prem is the full convexity residual** (`Γ/Prem = Return1σ − Δ/Prem`, so the additive identity still holds exactly). The old Taylor dollar fields (`pnl1pct`/`pnl1sigma`/`pnl2sigma`) are gone.
- **MC expectancy columns** (same zero-drift paths as P(+X%), all commission/haircut-aware, `spread_mc_stats`): **P(prof exp)** = terminal Adjusted P&L > 0 at expiration; **Med d→tgt** = median first-touch day among target-hitting paths; **EV %** = expected Adjusted P&L (% of cost) under exit-at-target (hitting paths bank the target, the rest ride to expiry — a conservative no-edge floor, usually negative). Hover popup adds P(−50%) loss tail and **Velocity** (target % ÷ median days). All ride into Scatter automatically.
- **Staleness flags**: each leg carries `lastTrade*` epochs; a leg untraded for > `STALE_TRADE_AGE_SECS` (1 day) vs. the scan flags the row with an amber ⚠ beside Premium (per-leg ages in the popup). The monitor flags individual legs in its Quote column the same way (vs. the snapshot's `quoteTime`).
- **Score column** (first column, default sort): a 0–100 composite for risk-adjusted capital efficiency, computed **client-side over the returned set** (percentile-rank blend of `returnAtMove`, `probTarget`, `gammaPrem`, `rewardRisk`, `thetaPrem`, times a `min(1, worstLegOI/target)` liquidity gate). Weights are tuned live via the collapsible **Score weights** strip above the table (sliders + Reset/Aggressive/Conservative presets), persisted in `localStorage`; re-weighting re-ranks instantly with **no new Yahoo scan**. It ranks *within the current scan* — re-read after any filter change. Full formula + worked example live in the plan file `~/.claude/plans/curently-we-are-getting-idempotent-rocket.md`.

## Monitor (`/positions`)
- Compact detail table (merged columns: Position, Quote, Entry/Liq, Cost/Value) + Portfolio Summary.
- **P&L and Adj P&L come in best/worst pairs** stacked in their cells: **best** = both legs exited at bid/ask mid (`pnl`/`adjPnl` fields), **worst** = pure liquidation, long sold at bid + short bought at ask (`pnlWorst`/`adjPnlWorst`). The **ntfy alerts, P(+X%) calibration, and P&L history all anchor to Best (mid)**; worst is the liquidation floor. Caveat: a leg with no live two-sided quote has mid = `max(bid, ask, last)`, so best degrades to the stale last (the ⚠ staleness flag marks those rows). **Adj P&L** = haircut on gains + round-trip commission. **Daily Theo P&L** = BS reprice for the underlying's 1-day move (spot − the underlying's prior close). That prior close must come from yfinance's `fast_info.regular_market_previous_close` — **never `previous_close`**, which yfinance derives from 1wk/1h *prepost* bars and so returns the prior day's last after-hours print (seen 2026-07-30: QQQ 666.07 vs the real 661.73 close, understating the day's move by ~0.7pp and Daily Theo dollars by ~23%). `YahooSource._prev_close` is the single chokepoint for both `get_previous_close` (Finder day move) and `get_underlying_quote`'s `regularMarketPreviousClose` (hybrid-spot monitor path); its fallback is the daily close series, never the prepost value. The summary's Daily Theo tile also shows **Daily MTM** = today's mid marks vs yesterday's marks (leg `prevClose` from Yahoo's per-contract `change` = trade-based official close; marketdata via the `get_option_prev_close` hook = **prior-session closing bid/ask mid** from historical EOD quotes — true mid-to-mid, works on untraded legs, business-day step-back with candle-close fallback; memoized per day in `_OPT_PREV_CLOSE_CACHE`; unavailable in test mode).
- **Yahoo's quote feed can freeze at a prior session's close** (seen 2026-07-14; `marketState` still says REGULAR) while its candle feed stays live. In live mode the monitor's spot path detects a quote older than `QUOTE_STALE_FALLBACK_SECS` (20 min) and falls back to the last 1-minute candle for spot **and the prior daily candle for prev close** (`_candle_spot_and_prev`) — the frozen block's `previousClose` is a session behind too, which would otherwise turn Daily Theo into a two-day move. Candle data only overrides when strictly newer (weekends keep the quote block); test mode never candle-falls-back (frozen data stays frozen). Raw/Adj P&L still reflect the option marks, which no spot fix can freshen. **Own-vol ±Nσ** and **β·index ±Nσ** columns use one shared reprice engine; **beta** is a 2yr daily regression vs. the index (default `^GSPC`), cached daily, with the index's σ from its VIX-family implied vol. The **Scenario P&L** summary box combines these, plus a **β-wtd Δ** row = Σ per-position `betaDollarDeltaPer1Pct` (theoretical $ P&L for a +1% index move) — the portfolio's aggregate calibrated leverage in index terms.
- Global controls: refresh interval, Adj P&L haircut %, profit target %, beta index, **Std devs** (σ multiplier driving all ±σ columns), **Auto-refresh** (master on/off switch for auto-polling — when off, only manual Refresh-now updates the table; `posAutoRefresh` localStorage, default on; independent of the interval and market-hours gate — effective polling = auto-refresh on AND not market-paused), **Market hours only** (default on: auto-refresh polls only 9:30–16:30 ET on trading days — client-side ET clock via Intl + a hand-maintained `MARKET_HOLIDAYS` list in the page JS; pauses at the close, resumes at the next open; manual Refresh-now and the initial page load are never gated).
- **Quote-age badges**: the spot (Position column) and each option leg (Quote column) carry their own `quoteAgeBadge` pill (fresh <2m / delayed / stale ≥30m) from their own quote timestamps — spot from the underlying quote time, each leg from its per-contract quote time (`leg.lastTrade` = marketdata `updated` / Yahoo `lastTradeDate`). They can legitimately differ now that hybrid spot puts spot and options on different feeds.
- **Adj P&L push alerts** (`check_pnl_alerts`): every live (non-test) `/api/positions/quotes` refresh sends an ntfy.sh phone push the first time a position's Adj P&L % rises above each threshold in `alerts.json` (default +2.5%, +5%) — latched once per (position, threshold) per calendar day, so re-crossings don't re-fire until the date rolls. The ntfy topic is a gitignored random secret printed in the startup banner; alerts only fire while something is polling the quotes endpoint (i.e. a monitor tab is open).
- **Half-hourly position digest** (`check_position_digest`, same topic): on the first live refresh inside each half-hour slot 9:30–16:30 ET on trading days, pushes every position's best (mid) Adjusted P&L $ + % and the portfolio total — max 15/day, latched per (slot, date) in `alerts.json` (`digest_sent`), disable with `"digest": false`. The client market-hours gate runs to 16:31 so the 16:30 slot can fire.
- **Backstop poller** (`start_alert_poller`, launched from `main()`): a daemon thread that calls `fetch_position_quotes` + both alert checks every `POLLER_INTERVAL_SECS` (5 min) while `_market_session_now()` (9:30–16:31 ET, weekday, not a `MARKET_HOLIDAYS` date — the server-side twin of the client gate). **Alerts and digests no longer depend on an open tab** — before this, a closed/sleeping/TEST-mode monitor tab silently dropped every slot it missed (seen 2026-07-27: no digest 12:30–14:30 ET with the server up throughout). It stands down when a live `/api/positions/quotes` landed inside the current interval (`note_live_quote_refresh`, called from the handler), so an open tab costs no extra vendor credits, and it reuses that tab's haircut/target/index/σ so server-driven alerts match the UI's numbers (defaults until a tab reports in). Vendor errors are caught per tick. Disable with `"poller": false` in `alerts.json`. `MARKET_HOLIDAYS` (Python) is the single holiday source, serve-time substituted into POSITIONS_PAGE as `__MARKET_HOLIDAYS__` — a third raw-string `.replace()` token alongside the Finder's `{RISK_FREE_RATE_PCT}` and Scatter's `__PNL_CHART__`/`__SPREAD_TOOLTIP__`.

## Scatter (`/scatter`)
- Two side-by-side, independently-configurable panels; each point is one spread, with the same row-hover popup as the Finder. Axes/color come from a shared `COLS` list (mirrors the results-table columns, incl. `score`).
- **Data handoff:** the Finder stashes its current results (with live Score) into `localStorage['finderScatterData']` and opens `/scatter` in a new tab. The Scatter page reads that key on load.
- **Live sync:** the Finder re-stashes on every search **and** on Score-weight changes (debounced), each write carrying a changing `ts`. An open Scatter tab listens for the `storage` event and re-reads/re-renders automatically, preserving the user's axis/color picks. So an open Scatter tab tracks the Finder; clicking Scatter again still opens a fresh tab.

## Curve (`/curve`)
- One spread repriced live across spot. **Click any row** on the Finder results table or the My Positions table to open it. Chart layers: faint expiry payoff, dashed **ghost** curve at today's DTE/IV (drawn only once a slider moves, so the sliders' effect is visible), solid purple live curve, profit/loss fills, and a green ring at the market mark for positions.
- **Two spot markers, deliberately:** the blue dashed line is the *immutable* current spot and never moves while dragging; the yellow line is the slider's what-if spot (hidden while it sits within half a step of "now"). The spot slider's `min` is offset onto spot itself so the step grid passes exactly through it.
- **Sliders:** spot (range ±15% around the strikes), days-to-expiry (0…dte), IV shift (**additive vol points**, −20…+20, matching the repo's "$ per 1 vol-point" vega convention). Redraws are `requestAnimationFrame`-coalesced and mutate cached SVG nodes — the chart is built once, never re-`innerHTML`'d except the tick groups. Note rAF doesn't fire in a background tab, so a hidden Curve tab defers its redraw until shown (this also means `await requestAnimationFrame` hangs when driving the page from CDP — call `redraw()` directly in tests).
- **Y-axis toggle** (`curveYMode`): P&L in dollars vs. raw spread value (0…width). One series function serves both; only the domain and the reference line differ.
- **Breakeven is solved, not inherited:** bisection on `value(S) − totalCost` under the current sliders, and commission-inclusive — unlike the server's premium-only `breakeven` field, which is shown separately as the expiry BE.
- **Data handoff:** each table has an adapter (`spreadCurveDescriptor(s)` / `positionCurveDescriptor(p)`) producing one normalized descriptor written to `localStorage['spreadCurve:<id>']`; `openCurve` opens `/curve?id=…` with a **window name derived from the id**, so re-clicking a row refocuses its tab while a different spread gets its own (two spreads can be compared). Keys older than 24h are pruned on each open.
- **Live sync:** both pages call `refreshOpenCurves(...)` after a refresh/search, which rewrites **only keys that already exist** — never creating them — firing the `storage` event an open Curve tab listens on. On such a refresh the spot slider follows the market only if it was still parked on "now"; a moved slider is left alone.
- **The monitor must ship its model inputs for this to be honest:** `fetch_position_quotes` exports `ivLongPct`/`ivShortPct`/`atmIvPct`/`ivSource`/`riskFreeRatePct`, because `p.long.iv` is the raw vendor IV that `_trusted_leg_iv` exists to reject. `_trusted_leg_iv` returns `(iv, source)` where source ∈ `leg|implied|atm|raw`; anything but `leg` puts a ⚠ note in the Curve toolbar (on the `atm` rung both legs share one vol and the skew is gone).

## Dip Scanner (`/dip`)
- Answers the *first* question of the dip-buy workflow — **which** large cap is in an attractive pullback right now — that the single-ticker Finder can't. `compute_dip_signals(symbols, force)` mirrors `get_betas`: **one batched `get_daily_closes_batch(watchlist, "1y")`** + one `get_daily_closes("^VIX","1y")`, **no option-chain calls**, cached per calendar day on disk (`dip_cache.json`; `?force=1` bypasses). EOD/daily-close based — a "from time to time" scan, not intraday.
- **Per-name signals** (`_dip_metrics_for`, pure — reusable/testable without a source): `pctBelow20` (% below 20-day SMA), `z10` (10-trading-day return in σ of realized daily vol, `sqrt(10)` scaling per the repo's `sqrt(1/252)` convention), `rsi2`/`rsi14` (`_rsi`, simple rolling gain/loss), `aboveTrend` + `pctAbove200`.
- **Composite `dipScore` 0–100**: `raw = 0.35*sBelow + 0.30*sZ + 0.25*sRSI + 0.10*sVix` (each sub-score mapped 0–100, deeper pullback → higher), then a **trend-gate multiply ×1 above / ×0.35 below** the long-trend MA — the same multiply shape as the Finder Score's liquidity gate. **The trend gate is the 200-day only** (falls back to 50-day if 200d history is short): a real dip is normally *below* the fast MA, so gating on the 50-day would reject the very setups we want ("buy dips in uptrends, not falling knives").
- **VIX IV-rank** is a **shared macro column** (percentile of today's `^VIX` within its 1y range), not per-stock: no historical stock IV is stored, so per-name IV rank isn't available (a future enhancement could persist daily ATM-IV snapshots per name using the `beta_cache.json` per-day pattern).
- **Handoff to the Finder:** each row's "Find spreads →" opens `/?ticker=SYM&preset=dip`; the Finder's boot reads those query params (`applyDipHandoff` IIFE), sets `#ticker`, and calls `applyDipBuyPreset()`. That preset now **bundles both** the dip-buy *filters* (`DIP_BUY_PRESET`, incl. a `minNetDelta` directional floor so it's modest-leverage, not a lottery ticket) **and** the Conservative Score tilt (`applyScorePreset('conservative')`), then auto-searches — so the one button is a full dip-buy *screen*, not just 7 filter fields. The same button also lives on the Finder toolbar (`dipBuyPresetBtn`).
- Routes: `GET /api/dipscan[?force=1]` → `{asOf, vixRank, candidates[]}` sorted by `dipScore` desc; `GET/POST /api/watchlist` read/replace the curated list (`load_watchlist`/`save_watchlist`, de-duped + upper-cased; seeds `DEFAULT_WATCHLIST` on first read).

- Solo repo, commits go **direct to `main`** (remote `github.com/marange63/CallSpreads`).
- `.claude/` is gitignored — it holds local settings and two personal slash commands: **`/pos`** (scope a request to the My Positions page) and **`/finder`** (scope to the Finder page).
